# 依赖安全维护

核对日期：2026年10月19日。IDEA 会把间接依赖的安全告警显示在引入它的 starter 或 common 依赖行；同一个底层库在多个服务中出现时，会重复显示。包无法解析、编译错误、JDK 弃用警告与依赖漏洞需要分别处理。

## 本次修复

Eureka 不依赖业务公共模块，启动类采用 `@SpringBootApplication` 的默认包扫描。注册中心无需加载 `common` 中的 JWT、内部调用鉴权与业务 Web 配置。Gateway 实际使用 `common.JwtCodec` 等公共代码，保留其 common 依赖。

父工程集中管理本次受影响的依赖，子模块不各自指定不同版本。Jackson 使用 BOM 同步所属组件，Netty 与 Tomcat 使用 Spring Boot 提供的统一版本属性。HttpClient 4、Bouncy Castle 和 ASM 是现有间接依赖的版本约束，没有因此增加新的业务能力或新的依赖用途。

## 公告与版本依据

- [Netty Extended CONNECT 公告](https://github.com/netty/netty/security/advisories/GHSA-w6j8-x45j-w75f)：列出4.2.18.Final为该项修复版本；本次统一采用4.2.19.Final。
- [Netty QUIC 公告](https://github.com/netty/netty/security/advisories/GHSA-mj35-3qqm-q387)：对应 CVE-2026-100665。
- [Jackson core 公告](https://github.com/FasterXML/jackson-core/security/advisories/GHSA-7hhh-6rmp-j9qf)与[Jackson databind 公告](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-wv8q-qhhj-9h54)：2.21.7与3.1.7是相关修复起点，本次采用同一版本线的后续补丁。
- [Apache Tomcat 11 安全公告](https://tomcat.apache.org/security-11.html)：区分各认证、HTTP/2和WebSocket问题的受影响范围。
- [FreeMarker 2.3.35](https://github.com/apache/freemarker/releases/tag/v2.3.35)：模板引擎维护版本。
- [Bouncy Castle 1.86 官方说明](https://www.bouncycastle.org/resources/new-release-bouncy-castle-java-1-86/)：列出 CVE-2026-17508、CVE-2026-71889、CVE-2026-71891 等修复。
- [Logback 官方发布说明](https://github.com/qos-ch/logback/releases)：1.6.3说明中记录 MDC 文件路径处理修复。
- [ASM 版本说明](https://asm.ow2.io/versions.html)：核对9.11及9.11.1的修复记录。

IDEA 使用的 Mend 数据与 OSV 的收录范围和更新时间不同。OSV 未命中不能代替对截图中 CVE 的单独核对；包版本落入公告范围，也不自动证明本站已启用相应漏洞所需的功能。例如本项目的 ASM 仅属于测试依赖。处理方式是更新版本并核对实际用途，保留安全检查。

## 验证与重新加载

```text
mvn -B -ntp -f backend/pom.xml package dependency:tree -DoutputFile=target/dependency-review.txt -DoutputType=text
```

PowerShell 中可给两个 `-D...` 参数各加一对单引号，以免终端拆分参数。每个模块的最终依赖树写入各自的 target 目录，不能只看 POM 中的属性值判断升级是否生效。

本次本机验证：所有模块构建通过，20项公共模块测试和4项隔离启动检查通过；复查七个模块的252组依赖坐标与版本（包含编译、运行和测试范围），OSV 当次查询未命中公告。另行按维护者公告和 CNA 记录核对了截图补充的 Netty、Bouncy Castle、Logback、Tomcat WebSocket及ASM问题。该结果是本次核查记录，不表示以后不会新增漏洞。

IDEA 操作：

1. 在 Maven 工具窗口执行“重新加载所有 Maven 项目”，以父工程 backend/pom.xml 导入完整模块集合。
2. 等待依赖下载与索引结束，再查看“易受攻击的依赖项”中的组件版本。
3. 重新启动 Eureka，再启动业务服务与 Gateway；正在运行的旧进程不会自动换成新依赖。

依赖更新不要求重建数据库或导入测试数据。隔离启动检查使用随机端口，不连接现有业务数据库或当前注册中心；测试公钥在结束后删除。
