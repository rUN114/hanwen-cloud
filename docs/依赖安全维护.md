# 依赖安全维护

## 2026年10月23日：数据库驱动与测试JSON依赖

- 父POM使用Spring Boot的`mysql.version`属性，把四个业务服务的Connector/J从9.7.0统一更新为26.10.0。该版本支持MySQL Server 8.4及以上；本次以独立MySQL 9.7.2实例验证。
- CVE-2026-113602涉及json-smart严格JSON校验的输入终止符绕过。截至本次核对，Maven Central最新仍是2.6.0，上游问题没有确认可用修复版。本项目没有使用JsonPath断言，父POM因此统一排除starter-test引入的`com.jayway.jsonpath:json-path`，连同其json-smart引入链一并移除，不保留缺少默认提供器的半套JsonPath。
- starter-test还直接声明了json-smart，因此同时排除json-path与json-smart两条入口。测试仍使用现有Jackson、JUnit、Mockito和HTTP检查。未来若新增JsonPath测试，需要重新评估修复版本或安全提供器，不能直接恢复旧依赖。
- 复核时发现依赖变化可能没有触发薄JAR重建，旧运行JAR仍带9.7.0。父POM已启用maven-jar-plugin的forceCreation，保证重新打包读取当前依赖。
- 实际验证：42项测试和完整打包通过；七个模块的最终依赖树均不再包含json-path、json-smart；六个运行JAR均无上述组件，四业务JAR均包含Connector/J 26.10.0。
- 数据库回归使用13307端口的独立实例：四个应用账号分别连接所属库成功；服务端预编译、中文和DECIMAL读写、事务回滚通过。写入只发生于会话临时表，没有修改正常教学数据库；验证后关闭独立实例。

依据：[Connector/J 26.10.0官方说明](https://dev.mysql.com/doc/relnotes/connector-j/en/news-26-10-0.html)、[Oracle安全公告](https://www.oracle.com/security-alerts/cpujul2026.html)、[json-smart上游问题302](https://github.com/netplex/json-smart-v2/issues/302)。本记录描述以上两类依赖的处理，不表示其他组件以后不会新增公告。正在运行的旧Java进程需要重新启动才能加载新JAR。

## 2026年10月19日：此前的依赖复核

核对日期：2026年10月19日。IDEA 会把间接依赖的安全告警显示在引入它的 starter 或 common 依赖行；同一个底层库在多个服务中出现时，会重复显示。包无法解析、编译错误、JDK 弃用警告与依赖漏洞需要分别处理。

## 本次修复

Eureka 不依赖业务公共模块，启动类采用 `@SpringBootApplication` 的默认包扫描。注册中心无需加载 `common` 中的 JWT、内部调用鉴权与业务 Web 配置。Gateway 实际使用 `common.JwtCodec` 等公共代码，保留其 common 依赖。

父工程集中管理本次受影响的依赖，子模块不各自指定不同版本。Jackson 使用 BOM 同步所属组件，Netty 与 Tomcat 使用 Spring Boot 提供的统一版本属性。HttpClient 4、Bouncy Castle 和 ASM 是现有间接依赖的版本约束，没有因此增加新的业务能力或新的依赖用途。

## 验证与重新加载

```text
mvn -B -ntp -f backend/pom.xml package dependency:tree -DoutputFile=target/dependency-review.txt -DoutputType=text
```

PowerShell 中可给两个 `-D...` 参数各加一对单引号，以免终端拆分参数。每个模块的最终依赖树写入各自的 target 目录，不能只看 POM 中的属性值判断升级是否生效。

本次本机验证：所有模块构建通过，20项公共模块测试和4项隔离启动检查通过；复查七个模块的252组依赖坐标与版本（包含编译、运行和测试范围），OSV 当次查询未命中公告。另行按维护者公告和 CNA 记录核对了截图补充的 Netty、Bouncy Castle、Logback、Tomcat WebSocket及ASM问题。该结果是本次核查记录，不表示以后不会新增漏洞。

IDEA 操作：

1. 在 Maven 工具窗口执行“重新加载所有 Maven 项目”，以父工程 backend/pom.xml 导入完整模块集合。
2. 等待依赖下载与索引结束，再查看“易受攻击的依赖项”中的组件版本。
3. 重新启动 Eureka，再启动业务服务与 Gateway；正在运行的旧进程不会自动换成新依赖。

依赖更新不要求重建数据库或导入测试数据。隔离启动检查使用随机端口，不连接现有业务数据库或当前注册中心；测试公钥在结束后删除。
