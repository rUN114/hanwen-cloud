# 代码结构与格式

## 后端

`backend` 保留 Maven 父工程、common、Eureka、Gateway 和四个业务服务。common 为共享协议、认证和校验代码；业务服务采用以下目录：

```text
src/main/java/org/hanwen/<业务>/
  Application.java    服务入口
  controller/         HTTP 接口
  service/            业务处理与本业务辅助逻辑
  client/             Feign 调用
  config/             Spring 配置
  mapper/             MyBatis-Plus 数据访问
  model/              数据实体
```

扫描范围仍为各服务根包和 common，Mapper 扫描仍指向 mapper，入口主类名不变。MyBatis-Plus 版本及 BaseMapper、QueryWrapper 的使用保持。数据表、接口地址和返回字段不因本次移动而改变。

## 前端

```text
frontend/src/
  api/                HTTP 客户端
  types/              共享数据类型
  stores/             会话状态
  composables/        Vue 组合函数
  utils/              CSV、名册、作业书案、修订比较等工具
  router/             页面路由
  data/               馆藏数据
  styles/             全局样式
  views/              按账号、课程、学习、作业、练习、学情等业务分组
  components/         按用途分组的共享组件
```

静态素材继续位于 public/assets。页面 URL 不随文件夹移动；全局 CSS 加载顺序保持，保留各样式的职责，不在本次整理中合并或改变覆盖规则。原 platform-v4.css 改名 teaching-workflows.css。

## 格式检查

Java 使用 google-java-format 1.37.0，AOSP 风格为4空格，关闭长字符串重排。工具来自 google/google-java-format 的官方 Release，SHA256 固定为：

```text
834b2a0c38cb774953322a84b5ca3f2f40dd3156650b3cd44d3b744345962f7a
```

本机工具下载在 `.local/tools/google-java-format-1.37.0-all-deps.jar`。全新环境从官方 Release 下载并核对哈希，再在项目根目录运行以下 PowerShell 命令：

```powershell
$sources = Get-ChildItem backend -Recurse -Filter *.java | Where-Object FullName -NotMatch '[\\/]target[\\/]'
java -jar .local/tools/google-java-format-1.37.0-all-deps.jar --aosp --skip-reflowing-long-strings --replace $sources.FullName
```

检查时将 `--replace` 换成 `--dry-run --set-exit-if-changed`。GitHub Actions 同样下载固定版本、核对哈希并执行检查。

前端 Prettier 是开发依赖，不进入生产运行依赖。Vue、TypeScript、CSS、JSON 和相关 JavaScript 检查统一格式：

```text
npm run format --prefix frontend
npm run format:check --prefix frontend
```

整理后仍需运行后端构建、前端类型检查和构建、相应逻辑测试及实际运行检查。格式正确不代表业务逻辑已经验证。


## 独立MySQL提交回归

`SubmitConcurrencyIT` 和 `AttachmentPurgeIT` 不在默认单元测试范围内。先在独立MySQL数据目录、14327端口导入 `database/assignment.sql`，确认会话时区为 `+08:00`，再使用 `it-db` profile。连接串默认设置数字偏移并同步数据库会话，通过 `hanwen.test.dataDir` 指定该实例实际Data目录；测试核对目录后才允许清理样本表，禁止连接现用教学库。

```powershell
mvn -B -ntp -f backend/pom.xml -pl assignment-service -am verify -Pit-db "-Dhanwen.test.dataDir=<独立Data绝对路径>"
```

这组检查使用真实事务代理、Mapper和MySQL，覆盖同内容并发重试、不同内容冲突，以及截止、关闭、归档限制，另在独立临时上传目录验证附件宽限期和重复清理。CI使用独立MySQL容器，记录时区表数量但不以数量拦截。未启用profile的 `mvn verify` 不连接该测试库。浏览器缺失课程检查另外使用隔离API样本，不能将其描述为完整后端链路验收。
